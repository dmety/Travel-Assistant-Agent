# 旅行助手需求文档

## 1. 项目目标

为结伴出游的学生提供 Java 控制台工具。用户用自然语言创建旅行方案，记录目的地、交通、住宿、景点和费用；邀请其他账号在不同电脑上共同编辑；系统核算预算、校验时间，并在服务重启后恢复历史数据。

## 2. 用户与权限

- 未登录用户：注册、登录。
- 创建者：创建、查看、编辑和删除自己的方案，邀请或移除成员。
- 成员：接受邀请后查看、编辑共享方案，可退出；不能删除方案或管理成员。
- 服务端必须验证每次请求的身份和方案权限，不能依赖客户端隐藏菜单。

## 3. 业务流程

注册登录 → 输入自然语言需求 → Agent 补问缺失信息并生成草案 → 用户修改确认 → 保存方案 → 邀请成员 → 成员接受并编辑 → 查看预算与校验结果。数据由共享服务保存，重新启动后读取。

## 4. 功能需求

### V1：基础协作规划

- 账号注册、登录；创建者邀请已注册用户，受邀者接受或拒绝。
- Agent 理解目的地、日期、预算和偏好等需求，生成草案；用户确认后保存。未核实的价格、开放时间等应标记。
- 支持多条方案的创建、查看、编辑、删除；区分短途周末游和长途跨省游，记录成员、交通、住宿、景点和预计费用。
- 汇总已填写的非负费用，缺失费用标记为待填写；检查返回时间不得早于出发时间。
- 两名成员同时编辑时检查版本，冲突时拒绝覆盖并提示重新读取。
- 服务端以本地文本文件持久化账号、邀请和方案；重启后恢复。

### V2：查询与完善

- 查询高德地点、天气、步行、驾车和公交路线；显示来源及查询时间。
- Agent 按需调用查询工具，结合结果提出行程调整；用户确认后保存。
- 检查各安排的时间范围及重叠；无效时间禁止保存，重叠提示用户确认。
- 提供成员留言、修改记录和分类预算。

### V3：决策与总结

- 成员添加候选地点并投票，用户决定最终选择。
- 记录预算上限和实际支出，展示预计、实际、差额和人均费用。
- Agent 结合现有数据提示风险并解释建议；用户确认后应用。
- 导出可阅读文本摘要，归档已结束方案。

## 5. 非功能需求与边界

- 多客户端须连接同一可访问服务；网络中断时无法共享编辑。
- 使用成熟密码哈希算法保存密码；密钥通过环境变量配置。
- 外部 API 超时、失败或数据不足时说明原因；既有方案仍可查看和编辑。
- 不提供酒店预订、支付或实时库存。数据文件需要定期备份。

## 6. 验收

V1：两台电脑完成注册、生成、邀请、编辑、冲突检查和重启恢复。V2：验证高德查询、工具调用、时间冲突和修改记录。V3：验证投票、预算分析、建议确认、导出归档。测试无权限访问、无效输入、外部接口失败和文件读写失败。
