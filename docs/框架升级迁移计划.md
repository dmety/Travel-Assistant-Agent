# 框架升级迁移计划（P1 · 暂存待裁定）

> 状态：**止血已落地，正式升级暂存**。本文是 4.x 大迁移的路线与影响面清单，供人工裁定目标线后实施；不是已完成的升级。对应 [生产就绪审计报告](../reports/current/生产就绪审计报告-2026-11-12.md) P1。

## 1 现状与已落地的止血

- 原版本 Spring Boot **3.5.7**，3.5 线 OSS 支持已于 **2026-06-30 结束**，此后不再有新免费安全补丁（同批停维的还有其锁定的 Spring Framework 6.2、Spring Security 6.5）。
- **止血已做**：根 `pom.xml` 跟随到 **3.5.16**——3.5 线最后的开源补丁。已核实其 parent POM 在 Maven 中央仓库可得（含 SHA1），并在本环境跑通全量回归：**travel-server 721 + travel-client 20 = 741 测试，0 失败 0 跳过，三模块 BUILD SUCCESS**。
- 止血只把版本推到本线最后补丁，**不改变 EOL 事实**：3.5.16 之后任何新披露的 Tomcat / Framework / Security 漏洞都不会再回补到 3.5 OSS。结构性风险仍在，必须正式升级。

## 2 目标线决策（需人工裁定）

审计给出两个候选，**选哪条是安全边界决策，须人工拍板后再实施**：

| 候选 | 取舍 |
| --- | --- |
| **4.0.8+** | 4.0 线已积累若干安全补丁（含 4.0.6 批次修复 8 个漏洞），相对成熟；是离开 EOL 3.5 的最低成本落点 |
| **4.1.x** | 更新的功能线，支持周期更长；但需确认其补丁成熟度与本项目依赖面兼容 |

裁定前不动主版本。裁定依据应包含：官方支持周期、目标线已披露 CVE 的修复状态、与本项目极小依赖面（web + security + validation）的兼容性。

## 3 迁移影响面（实证）

下列数字为本仓 grep 实测，非估算：

- **Jackson 是迁移主体**：`com.fasterxml.jackson` 共 **170 处、跨 103 个文件**（主代码 DTO/域模型/各 Store/Agent SPI/客户端 + 几乎全部测试基类）。审计指出 Boot 4.0 引入 **Jackson 3**，包路径由 `com.fasterxml.jackson` 重构（社区经验为 `tools.jackson`），这 103 个文件的 import 与部分 API 需逐一迁移。**确切的新包名与 API 差异须在实施前对照官方 Boot 4.0 / Jackson 3 迁移指南核实**（本计划编写环境无法访问外网，不臆断具体包名）。
- **jakarta 命名空间**：`jakarta.*` / `javax.*` import 共 **21 处、14 文件**（servlet/validation）。Boot 3 已完成 javax→jakarta 迁移，3→4 **无需再改命名空间**；但 Spring Security 7 / Framework 7 可能调整其中部分 API（如 Security 过滤链 DSL），需按官方迁移指南复核。
- **JDK 基线**：本项目已是 **Java 21**（根 pom `java.version=21`），满足审计所述 4.0 的 JDK 21+ 要求，无需再升 JDK。
- **依赖链整体移动**：升级不是改版本号——Spring Framework 7、Spring Security 7、Jackson 3、Tomcat 11 等随 Boot 4.0 BOM 一起动。本项目无 Actuator / devtools / fastjson / CloudFoundry，依赖面小，反而降低了迁移面（也挡掉了最严重的 Actuator 类 CVE，见审计 P1）。
- **配置与契约**：`application.yml` 的配置键、`tools/agent/provider-contract.json` 契约单一源、JaCoCo 阈值、surefire/failsafe 约定需随升级复核；覆盖率门禁（BUNDLE LINE 0.83 / BRANCH 0.64）迁移后必须复跑。

## 4 CVE 复核（需人工，未完成）

审计 P1 已按真实依赖面核定：CVE-2026-22733 / 40975 / 40977 / 16723 及 4.0.6 批次 Critical 在本项目**当前配置下均不适用**（无 Actuator / 无 `${random.value}` / 无 ApplicationPidFileWriter / 用 Jackson 非 fastjson）。**仍待人工复核**：

- **CVE-2026-22731**：受影响区间 3.5.0–3.5.11，触发条件未完全核实。本项目原 3.5.7 在区间内，止血到 3.5.16 已超出该区间，但确切组件与触发前置须对 `spring.io/security` 与 NVD 人工核实后定级。
- **4.0.6 / 3.5.14 批次 Critical** 的确切组件：须人工对官方安全公告核实，确认目标线已修复。

> 本计划编写环境无法访问外网（且任务约束禁止擅自替换 URL/代理），上述 CVE 的官方核实留待人工在可信网络下完成，不在此臆断结论。

## 5 分阶段实施路线（裁定目标线后）

审计估计整链迁移 **6–14 周**。建议顺序：

1. **兼容性清单**（1 周）：对照官方 Boot 4.0 迁移指南，逐条列出本项目用到的 API 在目标线的变更/移除；确认 Jackson 3 新包名与 API 差异；产出 103 个 Jackson 文件的迁移映射。
2. **独立分支迁移**（2–4 周）：在分支上先升 BOM，再按「域模型/DTO → Store → Agent SPI → 控制器 → 安全配置 → 测试基类」顺序迁 Jackson 与 Security API；每步跑定向测试。
3. **全量回归**（1–2 周）：`mvn clean verify` + JaCoCo 门禁 + `tools/acceptance.py` + G0 契约门禁全绿；并发/乐观锁/级联删除等关键用例重点复核。
4. **灰度与切换**（1–2 周）：先只读观察，再开放写入；保留 3.5.16 产物作回滚点。
5. **收尾**：同步修订架构文档、接口文档、部署说明与本计划的状态。

## 6 回滚

- 升级期间**保留 3.5.16 的可运行产物与分支**；4.x 未通过全量回归与灰度前不切换生产。
- 回滚即切回 3.5.16 产物（数据格式不变，JSON 持久化与 4.x 无关，无需数据回滚）。
- 止血版本 3.5.16 本身可长期运行，但须尽快推进正式升级，不应把 EOL 线当长期落点。
