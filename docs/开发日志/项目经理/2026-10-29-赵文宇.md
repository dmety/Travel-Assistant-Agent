## 一、今日工作

### 1. 明确需求与项目范围

结合课程背景，对旅行助手的目标和操作流程进行了多轮梳理。确认面向学生结伴出游，采用 Java 控制台交互，记录目的地、交通、住宿、景点和预算，支持短途周末游与长途跨省游。

明确多人协作为不同账号互相邀请、接受后在不同电脑上编辑同一旅行方案；自然语言是创建方案的主要入口，由 Agent 生成草案供用户修改和确认。将文本持久化的位置确定为共享服务端本地，以满足跨电脑共享和重启恢复的需要。

### 2. 划分三个迭代版本

将项目按可独立运行的阶段交付，而非一次完成所有功能：

- V1：账号与邀请、自然语言规划及本地工具、共享方案编辑、基础预算与日期校验、文本存储。
- V2：高德地点、天气与路线查询，Agent 外部工具调用，详细时间检查、留言和修改记录。
- V3：候选项投票、实际支出与预算分析、综合建议、导出与归档。

### 3. 完成设计与技术选型

整理需求文档、业务功能技术实现方案、架构设计和各版本功能说明；制作 C4 容器图与后端组件图，说明系统边界、运行单元、组件职责和主要调用关系。

确定 Java 21、Maven、Spring Boot、Spring Security、Spring AI、DeepSeek、高德 Web API、Jackson 和 Java NIO 等技术。认证终版选择服务端会话与 BCrypt，不使用 JWT；多人修改采用方案版本号及服务端锁。确定 Agent 的修改结果必须由用户确认，并经过业务服务权限和规则校验后保存。

补充项目结构和设计理由，明确客户端、共享契约与后端的模块边界，以及后端接口、应用服务、领域与基础设施的分工。

### 4. 建立工程与验证基础

借助 AI 编程工具建立 travel-client、travel-common、travel-server 三个 Maven 模块，完成后端启动入口、健康检查、安全配置、客户端连接入口和接口测试。移除原数据库构建依赖，按文本存储方向预留业务模块。

完成 Java 21 环境下的构建验证，并修正客户端打包配置冲突。当前工程骨架可启动和连接，但各业务模块仍需后续开发。

### 5. 整理协作资料与代码管理

将设计资料及图片整理到 docs 目录，修正相对链接，创建项目经理、开发负责人、测试负责人、文档负责人四个工作日志目录。

初始化本地 Git 仓库，采用直接的中文提交说明。合并 GitHub 远程初始化内容，保留许可证并整合 README，将工程与文档推送至 main 分支。

## 四、问题与处理

- **文本存储与跨电脑协作容易混淆**：统一为共享后端读写服务端本地文本文件，客户端通过网络操作。
- **初版架构图表达不清**：改为 C4 容器与组件视图，区分系统边界和后端内部职责。
- **旧工程方向与终版不一致**：移除 MySQL/JPA 构建依赖；旧骨架由项目经理确认删除。
- **客户端打包配置冲突**：修正 Maven Shade 配置合并方式，重新构建通过。
- **设计材料存在同步风险**：后续应按终版架构统一其他文档中较早的认证及 Agent 描述，避免组员依据不同版本开发。
