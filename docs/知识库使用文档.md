# 中国旅游景点知识库 — 开放使用文档

> Travel-Assistant-Agent 的核心数据底座，覆盖全国 **37 个主要旅游城市、11,862 景点**，  
> 融合 **OpenStreetMap（开源基底）** 与 **高德 Amap（国内权威补强）** 双源数据，  
> 含 **5A 景区 134 个、4A 景区 562 个**，等级/评分/开放时间/电话/图片覆盖全面。

---

## 1. 数据源说明

| 数据源 | 性质 | Key 要求 | 覆盖 | 许可 | 角色 |
|---|---|---|---|---|---|
| **OpenStreetMap / Overpass** | 开源众包 | 无需 Key | 全球（国内一般） | ODbL（允许缓存/存储/修改） | **基底**：名称/坐标/类型/城市/省份 |
| **高德 Amap Web 服务** | 商业服务 | 需申请 Key（个人免费额度约 5000 次/天） | 国内最全 | 商业（免费额度） | **补强**：等级/评分/开放时间/票价/电话/图片 |

**融合策略**：OSM 作全球基底，高德按 `(省, 归一名)` 匹配补强字段；OSM 未覆盖的城市（如西部/边缘城市由 Overpass 超时跳过的）由高德独立补入。

## 2. 数据字段定义

每条景点记录包含以下字段：

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `id` | string | 唯一标识（`osm-node-xxx` / `amap-xxx`） | OSM 或 Amap |
| `name` | string | 景点名称 | OSM + Amap |
| `name_zh` | string | 中文名（OSM 专用） | OSM |
| `type` | string | 类型/分类（如 `museum`、`风景名胜`） | OSM + Amap |
| `city` | string | 所属城市 | OSM + Amap |
| `province` | string | 所属省/直辖市/自治区 | OSM + Amap |
| `lat` | float | 纬度（WGS-84 / GCJ-02 混合，详见限制） | OSM + Amap |
| `lon` | float | 经度 | OSM + Amap |
| `address` | string | 详细地址 | OSM + Amap |
| `level` | string | A 级等级（如 `5A景区`、`4A景区`） | Amap `keytag` |
| `tags` | list | 高德标签（如 `["5A景区", "文物古迹"]`） | Amap |
| `rating` | string | 评分（如 `4.9`） | Amap |
| `open_time` | string | 开放时间描述 | Amap |
| `ticket` | string | 票价信息 | Amap |
| `tel` | string | 联系电话 | Amap |
| `website` | string | 官方网站 | OSM |
| `image` | string | 主图 URL | Amap |
| `photos` | list | 图片 URL 列表 | Amap |
| `wikidata` | string | Wikidata 实体 ID（如 `Q37921`） | OSM |
| `description` | string | OSM 描述 | OSM |
| `source` | string | 数据来源标记（`OpenStreetMap` / `Amap` / `OpenStreetMap + Amap`） | 融合 |
| `sources` | list | 多源标记列表 | 融合 |

## 4. 构建与重跑

### 环境准备

1. **Python 3.10+**（项目使用 WorkBuddy 内置 Python）
2. **高德 API Key**：在项目根目录创建 `.env` 文件：
   ```
   AMAP_API_KEY=你的高德Key
   ```
   > `.env` 已被 `.gitignore` 排除，不会进仓库。  
   > 高德 Key 申请：[高德开放平台](https://lbs.amap.com/) → 注册 → 控制台 → 应用管理 → 添加 Key（选 Web服务）

### 构建命令

```bash
# 步骤 1：OSM 基底（免费、无需 Key，约 10-30 分钟）
python tools/build_china_kb.py            # 种子 8 城
python tools/build_china_kb.py --all      # 全部 37 城

# 步骤 2：融合 OSM + 高德（需 .env 中配置 AMAP_API_KEY，约 5-8 分钟）
PYTHONPATH=tools python tools/build_unified_kb.py

# 步骤 3（可选）：著名景点字段补全（按名称精确搜索补票价/电话，约 5-15 分钟）
PYTHONPATH=tools python tools/enrich_famous.py

# 单城验证（不落库）
PYTHONPATH=tools python tools/build_unified_kb.py --test-city 北京
```

### 高德 API 调用量估算

| 步骤 | 每城市调用数 | 37 城总调用 | 说明 |
|---|---|---|---|
| `build_unified_kb.py` | ~9 页 | ~330 次 | POI 分页搜索 |
| `enrich_famous.py` | ~1 次/景点 | ~4900 次 | 按名称精确搜索 |

> 个人开发者每日免费额度 **5000 次**。`build_unified_kb` 安全；`enrich_famous` 如超限可分两天跑。

## 5. 检索 API 用法

`tools/kb/query.py` 提供四种检索方式，Agent 可直接调用：

```python
from kb.query import load, by_city, by_type, search, nearby, stats

# 加载知识库
doc = load()

# 查看统计
print(stats(doc))
# {'count': 11862, 'osm_count': 4073, 'with_level': 800, ...}

# 按城市检索
beijing = by_city(doc, "北京")      # 北京所有景点

# 按省份检索（与 by_city 同接口，传入省份名即可）
hubei = by_city(doc, "湖北省")

# 按类型检索
museums = by_type(doc, "museum")    # 所有博物馆
scenic = by_type(doc, "风景名胜")    # 风景名胜类

# 按名称/地址模糊检索
palaces = search(doc, "故宫")        # 名称或地址含"故宫"的
lakes = search(doc, "西湖")          # 含"西湖"的

# 按坐标 + 半径检索（单位：公里）
near = nearby(doc, 39.9, 116.4, 5)  # 北京中心 5km 内景点
```

### 组合检索示例

```python
# 北京的博物馆
bj_museums = [a for a in by_city(doc, "北京") if "museum" in (a.get("type") or "")]

# 5A 景区
top_a = [a for a in doc["attractions"] if a.get("level") == "5A景区"]

# 有评分且评分 >= 4.8
high_rated = [a for a in doc["attractions"]
              if a.get("rating") and float(a["rating"]) >= 4.8]
```

## 6. Agent 接入指南

### Spring Boot (Java) 接入

知识库 JSON 可通过以下方式供 Java Agent 使用：

**方式 A：启动时加载到内存**

```java
// 在 Spring 配置类中
@Bean
public Map<String, Object> attractionKb() throws IOException {
    ObjectMapper mapper = new ObjectMapper();
    return mapper.readValue(
        new File("data/china_attractions.json"),
        new TypeReference<Map<String, Object>>() {}
    );
}
```

**方式 B：作为静态资源由前端/Agent 按需请求**

```java
@RestController
@RequestMapping("/api/kb")
public class KbController {
    // 按城市返回景点
    @GetMapping("/city/{name}")
    public List<?> byCity(@PathVariable String name) { ... }
    // 按关键词搜索
    @GetMapping("/search")
    public List<?> search(@RequestParam String q) { ... }
}
```

### Python Agent 接入

```python
from kb.query import load, search, by_city

doc = load()

def answer(question: str) -> str:
    """Agent 主逻辑：从知识库检索景点信息。"""
    # 简单示例：提取城市名或景点名进行检索
    results = search(doc, question) or by_city(doc, question)
    if not results:
        return f"知识库中未找到与「{question}」相关的景点。"
    top = results[0]
    info = [top["name"], f"城市: {top.get('city', '')}"]
    if top.get("level"):
        info.append(f"等级: {top['level']}")
    if top.get("rating"):
        info.append(f"评分: {top['rating']}")
    if top.get("open_time"):
        info.append(f"开放时间: {top['open_time']}")
    if top.get("ticket"):
        info.append(f"票价: {top['ticket']}")
    if top.get("tel"):
        info.append(f"电话: {top['tel']}")
    return "\n".join(info)
```

## 7. 已知限制与后续增强

| 限制 | 原因 | 可能解法 |
|---|---|---|
| **票价覆盖低**（约 56 条） | 高德 POI 搜索接口不返回景区门票价，`biz_ext.cost` 多为演出/活动票价而非景区门票 | **需人工补录**全国 5A/4A 景区门票价（约 700 条），或接入专门票价数据源 |
| **OSM 坐标为 WGS-84，高德为 GCJ-02** | 两个坐标系不同，偏差约 50-500m | 如需统一，对 OSM 坐标做 GCJ-02 偏移转换 |
| **维基百科简介不可用** | 本机/国内网络无法访问 Wikidata/Wikipedia | 境外部署时可用；或接 OpenTripMap 补维基摘要 |
| **西部/边缘城市 OSM 覆盖一般** | Overpass 对边缘城市查询易超时 | 已由高德补齐，数据来自高德而非 OSM |
| **部分景点重复**（如"黄鹤楼"与"黄鹤楼公园"） | 跨源名称不完全一致 | 可后续做更智能的名称归一化合并 |

### 可选增强方向

1. **OpenTripMap 第三源**：旅游专用、ODbL 开源，填免费 Key 即可，补维基摘要+图片（境外可用）
2. **景区门票价人工补录**：全国 5A/4A 景区门票价约 700 条，高德 API 不返回此字段，需人工整理后 merge 进知识库
3. **智能去重**：基于名称相似度 + 坐标距离的跨源合并，减少重复
4. **向量检索**：对景点名+描述做 embedding，支持语义搜索（"适合亲子游的景点"）
5. **增量更新**：定期重跑构建脚本，保持知识库时效性
