## 四、缺陷详情

### 4.1 P1-2：PDF 导出测试的平台适配缺口

`GuidePdfControllerTest.platformTestFont()` 的字体候选列表只有两支：

- Windows：`C:/Windows/Fonts/arial.ttf`、`simhei.ttf`
- 其他（else 分支）：`/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf` 等三条 Linux 路径

macOS 走 else 分支，而这三条路径在 macOS 上均不存在，`filter(Files::isRegularFile)` 全部落空后直接抛 `IOException`。

本机实测：`/System/Library/Fonts/Supplemental/Arial.ttf`、`Times New Roman.ttf`、`SFNS.ttf` 均存在，**机器有可用字体，是测试没有去登记 macOS 路径**，不属于业务代码缺陷。

影响面比单个用例更大：该用例承担 `GuidePdfController` 渲染分支的覆盖，跑不起来会使 `interfaces.rest` 包行覆盖率停在 0.92，连带触发 jacoco 门禁失败。因此本机在修复前无法让官方五步入口整体转绿。

同类问题在 `chineseLongTextSurvivesWrappingAndPagination` 上处理方式不同——该用例用 `@EnabledIfSystemProperty(named="os.name",matches="Windows.*")` 显式限定平台，非 Windows 直接跳过。两处标准不一致，建议统一。

修复方向（未执行）：else 分支补充 macOS 候选路径，或对无法提供字体的平台用 `@EnabledOnOs` 显式跳过。
