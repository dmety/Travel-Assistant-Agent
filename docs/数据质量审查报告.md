### P0-2 `rating` 全部为字符串（类型不一致）

- 非空 rating **4973** 条，类型分布：**{'NoneType': 6885, 'str': 4973}**（全部 `str`，无 `float`）。
- 数值范围 0.0–5.0；`lat/lon` 是 `float`，`rating` 却是字符串，schema 不一致。
- `rating=0` 共 **2** 条（天津滨海文化中心, 南亚学校），0 分通常代表“无评分”，应置 `null`。

**影响**：数值比较/排序/均值会按字符串处理出错（如 `'10'` < `'9'`）；与 lat/lon 的类型契约不一致。

**建议**：`rating` 统一转 `number`（float），`0` → `null`。风险：中（需确认下游无“按字符串拼接”逻辑；当前 Java 侧尚未接入 KB，风险可控）。

## 五、审查方法（复现口径）

对 `data/china_attractions.json` 做**只读全量扫描**，逐条校验以下维度（Python 3，未修改文件）：

1. **字段覆盖率**：每个字段的缺失/空串/空数组计数。
2. **元数据一致性**：顶层 `count/with_*` 与按条实际统计比对。
3. **类型契约**：`lat/lon`（float）、`rating`（应为 number）、`photos/tags`（list）等类型分布。
4. **枚举合法性**：`level`、`coordinateSystem`、`ticket_status/open_time_status` 取值集合。
5. **坐标有效性**：是否数值、是否落在合理经纬度区间。
6. **重复检测**：`id` 唯一性、同坐标、同省同城同名。
7. **地址质量**：`address == 省+市` 或长度阈值（<4）按来源分组统计。
8. **文本卫生**：首尾空白、不可见字符、极短/占位描述。
9. **归属核对**：按省份/城市 + 名称关键词/繁体字 + 坐标区间识别疑似错归属（如香港 POI 归深圳）。
