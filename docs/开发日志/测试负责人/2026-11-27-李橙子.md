3. **步骤 4 失败归因**：直接读失败堆栈与测试源码，`platformTestFont()` 的 `os.name` 判断只分了 Windows / 非 Windows 两支，非 Windows 分支全是 Linux 字体路径；再用 `ls` 确认 macOS 的 Arial.ttf 存在，排除「本机缺字体」，判定为测试代码的平台覆盖缺失。
4. **诊断与官方结论的区分**：官方入口 `acceptance.py` 失败即按失败记录；诊断打包产出的 41/41 与客户端 26/26 只用于定位阻塞范围，结论一律标注「诊断，不计入官方验收」。
