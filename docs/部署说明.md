# 部署说明

面向把本服务从「本地演示」推向「对外可用」的运维清单。本地开发启动方式见 [README](../README.md) 第 2 节，环境变量全表见 README「可选配置」；本文只讲生产部署关心的硬化项，对应生产就绪审计 P3/P5/P6。

> 框架生命周期提醒：3.5 线 OSS 支持已于 **2026-06-30 结束**，不再有免费安全补丁。本轮已止血升级到该线最后开源补丁 **3.5.16**（全量 741 测试通过）；但 3.5.16 仍属 EOL 线，正式升级 4.0.8+/4.1.x 需整条依赖链迁移（JDK 21+、Jackson 3、包路径重构），属多周工程，路线与影响面见 [框架升级迁移计划](框架升级迁移计划.md)。升级前不要把本服务暴露到不可信网络。

## 1 单实例定位（P6）

运行态用 JSON 文件持久化，原子写盘（temp + ATOMIC_MOVE）保证单进程内一致，但**不支持水平扩展**：

- 多个实例共享同一 `data/` 会互相覆盖；各实例的内存态（限流计数、会话、模糊查询缓存）也不共享。
- 登录/注册限流是**进程内滑动窗口**，重启归零；多实例下限流会被绕过。
- 会话是容器内存态 `HttpSession`，多实例需要 Spring Session 共享存储（未落地）。

**结论：本期只部署单实例。** 需要多实例或更强一致性与容量时，走 [数据库设计](数据库设计.md) 的迁移方案（引入 MySQL + JDBC Store + 行锁乐观锁），那是单独评审的多周工程，不在本次部署范围。

## 2 环境变量（生产关键项）

密钥只经环境变量注入，**绝不写进仓库、镜像或日志**。完整表见 README，生产必须显式设置的：

| 变量 | 生产取值 | 说明 |
| --- | --- | --- |
| `SESSION_COOKIE_SECURE` | `true` | 经 HTTPS 终止后必须置 true，否则会话 Cookie 随明文泄漏 |
| `AGENT_ADMIN_TOKEN` | 强随机值 | Provider 管理端点独立令牌；**留空即 fail-closed，所有管理请求 403** |
| `TRAVEL_DATA_DIR` | 持久卷路径 | 运行态业务 JSON 目录，需可写、需备份 |
| `ATTRACTION_KB_PATH` | 索引文件路径 | 只读景点索引，缺失则搜索降级（不影响行程/账号/协作） |
| `LOG_DIR` | 持久卷路径 | 日志目录，默认 `logs/`，`*.log` 不入库 |
| `SERVER_PORT` | `8080` | 反代 upstream 端口 |
| `SHUTDOWN_TIMEOUT` | `20s` | 优雅停机每阶段最长等待 |

`AMAP_KEY` / `BAIDU_AK` / `DEEPSEEK_API_KEY` 按需配置；留空则对应能力降级或返回 503，本地能力不受影响。

## 3 HTTPS 终止（P5）

服务自身只监听 HTTP，TLS 由反向代理终止。以 nginx 为例：

```nginx
server {
  listen 443 ssl;
  server_name travel.example.com;
  ssl_certificate     /etc/ssl/travel.crt;
  ssl_certificate_key /etc/ssl/travel.key;

  location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
```

- 置 `SESSION_COOKIE_SECURE=true`，并把 80 端口 301 到 443。
- **限流按真实 IP**：服务在反代后，必须先让 Spring 处理 forwarded headers（`server.forward-headers-strategy=framework` 或 `native`），否则限流会把所有请求算到反代 IP 上。本期默认未开启 forwarded 处理，单实例直连或可信反代下按需在 `application.yml` 显式打开并复核。
- CSRF 当前禁用，依据是 SameSite=Strict + 第一方同源（见 `SecurityConfiguration` 注释）。若将来引入跨站表单或第三方嵌入，须重新评估并开启 CSRF。

## 4 优雅停机（P5）

`application.yml` 已设 `server.shutdown=graceful` 与 `spring.lifecycle.timeout-per-shutdown-phase`。收到 SIGTERM 后先拒新请求、放行在途请求再退出：

- `docker stop`（默认 SIGTERM，10s 后 SIGKILL）——把 docker stop 超时调到 ≥ `SHUTDOWN_TIMEOUT`。
- `systemctl stop` 默认 SIGTERM，直接生效。
- 滚动重启时配合反代健康摘流（见第 5 节），不丢在途请求。

## 5 健康监控（P3）

`GET /api/health` 是就绪探针，**匿名可读**：

- 数据目录可写 → `200` + `{"status":"UP","application":"travel-assistant"}`。
- 数据目录不可写 → `503` + `{"status":"DOWN",...}`。JSON 持久化是唯一写依赖，不可写即无法落盘，反代/监控应据此摘流告警。
- 景点知识库只读、缺失时仅搜索降级，**不纳入**就绪判定（KB 状态另见 `/api/attractions` 相关接口）。

监控建议：对 `/api/health` 非 200 或 `status != "UP"` 告警。本期未引入 Actuator/metrics（见第 8 节取舍）。

## 6 日志（P3）

`logback-spring.xml`：控制台沿用 Spring Boot 默认，另加按天+大小滚动的文件落盘。

- 路径 `${LOG_DIR:-logs}/travel-assistant.log`，单文件 20MB、保留 30 天、总量上限 500MB。
- `*.log` 已被 `.gitignore` 忽略；生产把 `LOG_DIR` 指到持久卷或采集目录。
- 异常堆栈只进服务端日志（`ApiExceptionHandler` 兜底不向客户端泄栈）；密钥仅 env 注入、不打印；日志不含用户隐私正文。
- 未引入 JSON 结构化日志编码器（需新依赖），如需对接 ELK/Loki 再评审。

## 7 备份与恢复（P6）

运行态业务 JSON（accounts/itineraries/invitations/comments/changelog/candidates/votes）含账号哈希与用户行程，**必须定期备份到项目外**：

```bash
# 备份到仓库外目录，按时间戳建子目录；只输出文件数与路径，不打印内容
python tools/backup_data.py /var/backups/travel --data-dir /app/data
```

- 脚本拒绝仓库内目标，避免备份误入 Git。备份目录权限收紧，**不进 Git、日志或交付清单**。
- 定时：Linux cron 或 Windows 任务计划程序每日跑一次，保留近 N 份。
- 知识库（`china_attractions.json` / `attractions_index.json` / `attractions/`）与购票规则已在 Git，可再生成，不在备份范围。
- **恢复**：先停写（停服务或置只读），把备份子目录里的 JSON 覆盖回 `TRAVEL_DATA_DIR`，再启动服务。切换窗口内停写，避免新写入与备份分叉。

## 8 容器化（P5，本地可选·不入库）

**`Dockerfile` 仅本地保留、不入库**：`.gitignore` 已忽略 Docker 相关文件，不推送 GitHub。克隆仓库后不含 `Dockerfile`，需自备后方可执行以下步骤。本地 `Dockerfile` 为多阶段构建（Maven+JDK21 编译 → JRE21 运行，非 root，镜像不含源码）。

```bash
docker build -t travel-assistant .
docker run -d --name travel \
  -p 8080:8080 \
  -v /srv/travel/data:/app/data \
  -v /srv/travel/logs:/app/logs \
  -e SESSION_COOKIE_SECURE=true \
  -e AGENT_ADMIN_TOKEN=<强随机值> \
  --stop-timeout 30 \
  travel-assistant
```

- **数据卷需先种入景点索引**：把 `python tools/build_attraction_index.py` 的产物 `attractions_index.json` 放进 `/srv/travel/data`，否则搜索降级。运行态业务 JSON 由服务自动创建。
- `--stop-timeout 30` ≥ `SHUTDOWN_TIMEOUT`，让优雅停机跑完。
- 密钥经 `-e` 或 secret 注入，不写进镜像。
- **未验证项**：本机无 Docker，`Dockerfile` 未能本地构建验证，按 `pom.xml` 实际产物（`travel-server-0.1.0-SNAPSHOT.jar`）与资源口径（构建时复制 `tools/agent` 契约源）编写。首次部署先 `docker build` 跑通再上线。

## 9 可观测性取舍（P3，暂存待裁定）

审计 P3 建议「引 Actuator + 结构化日志 + 深健康检查」。本次落地了**深健康检查**与**logback 文件日志**（均无新依赖）。**Actuator/metrics 暂不引入**，原因是一项安全取舍：

- 审计 P1 的 CVE 核定指出，本项目「极小依赖面（无 Actuator）」恰好挡掉了最严重的 Actuator 类漏洞（CVE-2026-22733 的 CF Actuator 路径误映射、4.0.6/3.5.14 批次的 Actuator 端点未授权访问 Critical）。
- 在 **EOL 框架 3.5.16**（3.5 线已止血但仍 EOL）上引入 Actuator，会重新打开这类未授权端点攻击面，且不再有免费补丁回补。
- 因此引入 Actuator 属安全边界决策：须先完成框架升级（P1）、再评估端点暴露与鉴权，由人工裁定后实施，不在本次自动修复范围。
