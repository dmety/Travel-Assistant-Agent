# 行程用例 UC-ITIN-001：杭州西湖三日游

> 适用分支：`zipei`　|　接口依据：[服务端REST接口文档](./服务端REST接口文档.md)
> 配套脚本：[`examples/itinerary_usecase_hangzhou.py`](../examples/itinerary_usecase_hangzhou.py)（41 条断言，退出码即结果）

一份从零开始的**完整行程用例**：两名用户、一次三日游，覆盖创建、五大板块填报、成员邀请与板块级授权、
越权拦截、乐观锁冲突、非法输入拦截、删除清理。可作为联调用例、演示脚本，也可当回归冒烟用例。

---

## 1. 用例概要

| 项 | 内容 |
|---|---|
| 用例编号 | UC-ITIN-001 |
| 用例名称 | 杭州西湖三日游（多人协作填报） |
| 参与者 | `alice`（行程归属者 owner）、`bob`（受邀成员） |
| 目标 | alice 建行程并填满五大板块，邀请 bob 负责交通与住宿，验证权限与并发控制正确 |
| 前置条件 | 服务已启动；`alice`、`bob` 已注册（脚本会自动注册）；两人密码同为 `Passw0rd123` |
| 后置条件 | 行程被 owner 删除，数据回到初始状态（账号保留） |
| 行程时间 | 2026-11-20（周五）至 2026-11-22（周日），三天两晚 |

## 2. 权限矩阵（本例实际授予）

| 参与者 | 查看 | 方案 PLAN | 每日 DAILY | 交通 TRANSPORT | 住宿 LODGING | 费用 EXPENSE | 成员管理 | 删除 |
|---|---|---|---|---|---|---|---|---|
| `alice`（owner） | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| `bob`（member） | ✅ | ❌ | ❌ | ✅ | ✅ | ❌ | ❌ | ❌ |

矩阵的「❌」不是摆设——脚本第 13 步就用 bob 去改费用，断言必须拿到 **403**。

## 3. 主成功流程

版本号是本用例的主线：**创建时 version=1，此后每次写操作 +1**，共 7 次写操作走到 v8。

| 步 | 操作 | 请求 | 期望 | 之后 version |
|---|---|---|---|---|
| 01 | 注册两人 | `POST /api/account/register` | 201（已存在则 409，可复用） | — |
| 02 | alice 登录 | `POST /api/login`（表单） | 200 + `JSESSIONID` | — |
| 02b | 未登录访问 | `GET /api/itineraries` | **401** | — |
| 03 | 创建行程 | `POST /api/itineraries` | **201**，`owner=alice` | 1 |
| 04 | 填方案 | `PUT /{id}/plan?version=1` | 200 | 2 |
| 05 | 填交通（2 条） | `PUT /{id}/transports?version=2` | 200 | 3 |
| 06 | 填住宿（1 条） | `PUT /{id}/lodgings?version=3` | 200 | 4 |
| 07 | 填每日安排（3 天 9 项） | `PUT /{id}/daily?version=4` | 200 | 5 |
| 08 | 填费用（5 条） | `PUT /{id}/expenses?version=5` | 200 | 6 |
| 09 | 读详情核对 | `GET /{id}` | 200，子项 `id` 已由服务端补全 | 6 |
| 10 | 邀请 bob | `POST /{id}/members?version=6` | 200，`editSections=[TRANSPORT,LODGING]` | 7 |
| 11 | bob 登录并查看 | `GET /{id}` | 200（成员默认有查看权） | 7 |
| 12 | bob 改签高铁 | `PUT /{id}/transports?version=7` | 200，改签生效 | 8 |
| 18 | 最终核对 | `GET /{id}` | 200，五板块齐全，费用合计 2292.00 CNY | 8 |
| 19 | 删除行程 | `DELETE /{id}` | 200（仅 owner） | — |

## 4. 异常与边界分支

这六条是本用例的重点，全部断言具体状态码，不接受「差不多」。

| 步 | 场景 | 请求 | 期望 | 断言要点 |
|---|---|---|---|---|
| 13 | bob 无 EXPENSE 权限却改费用 | `PUT /{id}/expenses?version=8` | **403** | 越权后 version 仍为 8（不落盘） |
| 14 | owner 拿过期版本提交 | `PUT /{id}/plan?version=5` | **409** | 响应头 `X-Version: 8` |
| 15 | 费用金额为负 | `PUT /{id}/expenses?version=8`，`amount=-999.99` | **400** | `{ "error": "费用金额不能为负数：-999.99（交通）" }` |
| 16 | 离店早于入住 | `PUT /{id}/lodgings?version=8`，11-22 入住 / 11-20 离店 | **400** | 错误信息带两日期与住宿名 |
| 17 | 邀请未注册用户 | `POST /{id}/members?version=8`，`ghost_user_999` | **400** | 错误信息提示「只能邀请已注册用户」 |
| 17a | 三次非法请求后 | `GET /{id}` | version 仍为 8 | 400/403 都不推进版本 |
| 17b | 创建行程标题为空白 | `POST /api/itineraries`，`title="   "` | **400** | 去空白后为空即拒 |
| 17c | 修改不存在的成员 | `PUT /{id}/members/nobody?version=8` | **404** | body `error="成员不存在"`，与「行程不存在」区分 |

## 6. 两种执行方式

### 6.1 一键跑完（推荐）

```bash
# 服务已启动在 8080
python examples/itinerary_usecase_hangzhou.py --base http://localhost:8080

# 保留行程，便于回 /app 页面查看
python examples/itinerary_usecase_hangzhou.py --base http://localhost:8080 --keep

# 只要断言结果，不打印最终 JSON
python examples/itinerary_usecase_hangzhou.py --base http://localhost:8080 --quiet-json
```

脚本只用 Python 标准库（`urllib` + `http.cookiejar`），无需 `requests` 或 `curl`。
输出每条断言的「期望 / 实际」，末尾汇总 `结果：41/41 通过`，失败时退出码为 1。

> **避免污染仓库数据**：脚本会注册账号、创建行程。若服务按默认 `./data` 启动，`data/accounts.json`
> 会多出 `alice`、`bob`。建议先用临时数据目录起服务：
>
> ```bash
> TRAVEL_DATA_DIR=F:/wb_tmp/uc_data java -jar travel-server/target/*.jar --server.port=8081
> ```
>
> 跑完删掉临时目录即可，仓库里的 `data/` 保持干净。

### 6.2 手工在页面点

1. 打开 `http://localhost:8080/login`，用 `alice` / `Passw0rd123` 登录（没有就先注册）。
2. 进 `http://localhost:8080/app`，创建行程，标题粘 §5.1。
3. 逐个板块点「读取」拿到 version，在编辑框粘入 §5.2–§5.6 的 JSON，点「保存」。
4. 成员区添加 `bob`，勾选 `TRANSPORT`、`LODGING`。
5. 退出后用 `bob` 登录，尝试改费用——页面会展示 403；改交通则成功。
6. 用过期 version 保存一次，可看到 409 与 `X-Version` 提示。

## 7. 验收标准

全部满足才算用例通过：

- [ ] 创建返回 201，`owner=alice`，`version=1`
- [ ] 五次板块写入均 200，version 依次 2→3→4→5→6
- [ ] 详情中子项 `id` 均已补全（交通 2、住宿 1、日程 3 天 9 活动、费用 5）
- [ ] 邀请 bob 后 version=7，成员列表含 `bob` 且权限为 `[TRANSPORT, LODGING]`
- [ ] bob 改交通成功（version=8），改费用 403 且版本不变
- [ ] 过期版本提交返回 409，响应头 `X-Version` 等于服务端最新版本
- [ ] 负数费用、离店早于入住、邀请未注册用户 三种输入均 400
- [ ] 400/403/409 均不推进版本号
- [ ] 删除仅 owner 可用，返回 200
