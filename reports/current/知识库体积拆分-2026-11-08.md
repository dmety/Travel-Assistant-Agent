# 知识库体积拆分（2026-11-08）

## 结论

`data/china_attractions.json` 的 6.30 MiB 单行文件不再作为编辑入口。按省切成 30 个小文件放在 `data/attractions/`，每个文件一条记录一行，最大的 `广东省.json` 为 524 KiB。主库字节未变，SHA256 仍是 `17164e1a…4661`；Java 加载链、运行索引和 `/api/attractions` 返回体零改动。

## 为什么要再拆一次

上午的内容分层按字段切，解决了「改一条记录只 diff 几行」，但 `content.json` 仍有 4.3 MiB，6.30 MiB 的单行主库也还在。用户要的是把大 JSON 本身拆开，不是按职责重组字段。两次拆分是正交的：一次按字段切，一次按记录切。

## 切法与数据

| 项 | 值 |
| --- | --- |
| 记录数 | 7,745 条 |
| 省份数 | 30 个，无空值 |
| 分片数 | 30 个省文件，另有 `manifest.json` |
| 分片合计 | 6.34 MiB |
| 最大分片 | `广东省.json`，524 KiB，728 条 |
| 最小分片 | `新疆维吾尔自治区.json`，82 KiB |
| 单片格式 | 一条记录一行，紧凑 JSON，不缩进展开 |
| 主库字节 | 6,609,331 字节，SHA256 不变 |

主库的 `attractions` 数组不按省聚簇，实测有 61 段省份交错。分片不能按文件名顺序拼接。`positions` 记下每条记录在原数组中的下标，合成时按下标归位，再按 `manifest.json` 的 `topLevelKeys` 组装顶层键，才能逐字节复现历史主库。`manifest.json` 同时保存 14 个顶层字段、65 条城市简介和分片清单。

分片文件不缩进展开，是体积与 diff 粒度的折中：缩进两格会把单条记录摊成几十行，文件反而变大；一行一条则改一条只动一行，体积接近原库。

## 职责链

```text
data/attractions/*.json              唯一编辑源
  -> data/china_attractions.json    产物，旧脚本与索引构建读它
  -> data/kb_modules/*.json         --sync 重建的字段视图，不手工改
  -> data/attractions_index.json    Java 只读索引
```

`data/kb_modules/` 从上一版的编辑源降级为派生视图，由 `--sync` 自动重建。这样只有一个编辑入口，不会出现两套源各自改动后互相覆盖。

## 命令

```bash
python -B tools/kb_shards.py --check     # 门禁第一步，分片与主库逐字节一致
python -B tools/kb_shards.py --sync      # 改完分片，一键贯通全链路
python -B tools/kb_shards.py --split     # 主库被旧脚本改动后，反向重建分片
python -B tools/kb_shards.py --assemble  # 只写回主库，不碰模块与索引
```

`--sync` 依次写回主库、重建 `kb_modules/`，再判断索引是否过期。索引顶层 `generated_at` 是构建时刻，`build_attraction_index.py --check` 明确忽略它；内容一致时跳过重建，避免这个 3.94 MiB 单行文件每次都整行进 diff。

## 实测

负例全部在副本上跑，工作区数据未被污染，临时副本已删除。

| 场景 | 期望 | 实测 |
| --- | --- | --- |
| 改分片票价，未同步 | 拒绝 | `exit=1` |
| 绕过分片直接改主库 | 拒绝 | `exit=1` |
| 缺一个分片 | 拒绝 | `exit=3` |
| 多出未登记文件 | 拒绝 | `exit=3` |
| 清单条数不符 | 拒绝 | `exit=3` |
| `positions` 重复 | 拒绝 | `exit=3` |
| 干净副本 | 通过 | `exit=0` |

正向链路：改一条分片记录的票价，跑 `--sync`，索引被重建；把分片改回，再跑一次 `--sync`，主库 SHA256 复原为 `17164e1a…4661`，`kb_shards --check`、`kb_modules --check`、`build_attraction_index.py --check` 三道全通过。索引字节随后还原为 HEAD 版本，消除仅时间戳变化带来的整行 diff。

幂等：分片与主库一致时再跑 `--sync`，输出「运行索引已与源库一致，跳过重建」，索引 SHA256 前后相同。
