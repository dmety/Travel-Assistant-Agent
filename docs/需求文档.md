## 1. 项目目标

为结伴出游的学生做一个行程规划工具。用户用自然语言描述出行需求，系统生成带来源的草案；邀请其他账号在不同电脑上共同编辑；系统核算预算、校验时间，重启后恢复数据。

11-09 起目标扩展了一条：用户不必填表，可以直接用对话的方式提问和修改，模型自己去查数据。

## 2. 用户与权限

- 未登录用户：注册、登录，可以查看景点与购票信息。
- 创建者：创建、查看、编辑、删除自己的行程，邀请或移除成员。
- 成员：接受邀请后查看、编辑共享行程，可退出；不能删除行程或管理成员。
- 服务端必须验证每次请求的身份和行程权限，不能依赖客户端隐藏菜单。

## 3. 业务流程

填表路径：注册登录 → 输入自然语言需求 → Agent 补问缺失信息并生成草案 → 用户修改确认 → 保存行程 → 邀请成员 → 成员接受并编辑 → 查看预算与校验结果。

对话路径：注册登录 → 打开对话页 → 提问（「下周六带爸妈去武当山玩四天，预算六千」）→ 系统解析意图与槽位 → 模型决定查哪些工具 → 回答并给出可点选的下一步。

两条路径共用同一套行程、权限与保存逻辑。对话只是入口不同。

## 4. 功能需求

### 4.1 V1：基础协作规划

- 账号注册、登录；创建者邀请已注册用户，受邀者接受或拒绝。
- 检索本地景点快照后生成带来源的草案，用户确认后保存。未知价格和开放时间要明确标记，费用未知不按零元处理。
- 支持多条行程的创建、查看、编辑、删除；区分短途周末游和长途跨省游，记录成员、交通、住宿、景点和预计费用。
- 汇总已填写的非负费用，缺失费用标记为待填写；返回时间不得早于出发时间。
- 两名成员同时编辑时检查版本，冲突时拒绝覆盖并提示重新读取。
- 服务端以本地文本文件持久化账号、邀请和行程，重启后恢复。

### 4.2 V2：查询与完善

- 查询地点、天气、步行、驾车和公交路线；显示来源及查询时间。
- Agent 结合查询结果提出行程调整，用户确认后保存。
- 检查各安排的时间范围及重叠。结束早于开始禁止保存，重叠只提示确认。
- 提供成员留言、修改记录和分类预算。
- 票务辅助：提供经核验的官方入口与已查询规则，显示来源和时间。未接入库存接口时显示「余票未核验」，无可靠入口时提示自行进入官方渠道。

### 4.3 V3：决策与总结

- 成员添加候选地点并投票，用户决定最终选择。
- 记录预算上限和实际支出，展示预计、实际、差额和人均费用。
- Agent 结合现有数据提示风险并解释建议，用户确认后应用。
- 导出可阅读文本摘要，归档已结束行程。

### 4.4 V3 之后增补：对话式交互

这一节的需求在 11-09 至 11-10 落地，原需求文档没有。

- **一句话解析**：用户说一句完整的话，系统拆出目的地、天数、人数、预算、偏好五个槽位。前端不做正则匹配。
- **地名归属**：用户说的地名可能是不在知识库里的县级地名。系统要判断它属于哪个城市，查不到就转实时检索，不能直接把问题丢回给用户。
- **对话回答**：模型看着工具清单自己决定查什么，查完再回答。工具至少覆盖景点检索、天气、餐饮、行程草案、购票建议、灵感候选、投票。
- **上下文记忆**：同一会话内，用户说「那说一下武汉」时能接上上一轮的语境。
- **对话不改数据**：对话只出建议，落库必须经用户确认。模型不能直接写文件。
- **可点选补问**：缺信息时给可选项，不让用户重打一遍。
- **降级要说清**：模型不可用时，如实说明降级原因，不假装查过。

### 4.5 未纳入范围

- 完整票务交易（下单、支付、出票、退改）。
- 酒店预订。
- 实时余票保证。
- 美食 Agent 的独立部署。

## 5. 非功能需求与边界

- 多客户端须连同一个可访问服务；网络中断时无法共享编辑。
- 密码用成熟哈希算法保存；密钥通过环境变量配置，不进仓库。
- 外部 API 超时、失败或数据不足时说明原因；既有行程仍可查看和编辑。
- 知识库字段必须区分「未知」与「已核验」，标记来源、时间及坐标系。发布融合库前核对数据许可，免费额度不等于分发授权。
- 单个进程串行写入。不支持多个实例同时写同一份文件。数据文件需定期备份。

## 6. 验收

**V1**：两台电脑完成注册、生成、邀请、编辑、冲突检查和重启恢复。另验证景点 ID 与证据可追溯、未知费用披露、检索失败和有限修订。

**V2**：验证地图查询、工具调用、时间冲突和修改记录。另验证购票入口、规则来源、库存未知及无可靠入口提示。

**V3**：验证投票、预算分析、建议确认、导出归档。要覆盖无权限访问、无效输入、外部接口失败和文件读写失败。

**对话能力**（11-10 起）：验证一句话解析出五个槽位、县级地名归位、会话内追问能接上语境、模型不可用时如实降级、对话不产生未确认的写入。

自动化验证（2026-11-12）：`mvn verify` 693 个测试通过，0 失败、0 错误、0 跳过；`tools/acceptance.py` 真实服务回归通过，含配置式本地模拟助手准入、调用与失败回退。静态测试数量不作为人工页面验收或真实外部接口成功的证明。

**正式交易扩展**（未启动）另需验证重复下单、超时查单、价格变化、支付与出票分离、回调校验及重启恢复。
