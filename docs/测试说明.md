> 最后更新：2026-11-04（V2 四块能力落地后）　|　适用版本：`wei` 分支

## 1. 环境前提

| 项 | 要求 | 说明 |
|---|---|---|
| JDK | **21** | 项目 `maven.compiler.release=21`，低于 21 无法编译 |
| Maven | **3.9 及以上** | 用于依赖解析与 surefire 执行 |
| 网络 | 可访问 Maven 中央仓库或镜像 | 首次执行需下载依赖 |
| 数据目录 | 无需预建 | 测试自行创建临时目录，见第 4 节 |

验证环境：

```bash
java -version    # 应输出 21.x
mvn -version     # 应输出 3.9.x（并显示其使用的 JDK 为 21）
```

> **没有 Maven 的机器跑不了测试。** 历史上有同学只能用 `javac --release 21` 做编译级验证，那种"通过"不代表测试通过。若本机确实没有 Maven，可用 IDE 内置版本（IntelliJ IDEA 自带 Maven 3 与 JBR 21，无需额外安装）。

## 2. 运行方式

以下命令均在**项目根目录**执行。

```bash
# 全量测试（推荐）
mvn test

# 全量构建并跑测试（含打包）
mvn clean verify

# 只跑服务端模块
mvn -pl travel-server test

# 只跑某个测试类
mvn -pl travel-server test -Dtest=ItineraryVersionTest

# 只跑某个方法
mvn -pl travel-server test -Dtest=ItineraryVersionTest#旧版本提交返回409

# 跳过测试打包
mvn clean package -DskipTests
```

测试报告输出在 `travel-server/target/surefire-reports/`，文本摘要可直接查看：

```bash
cat travel-server/target/surefire-reports/*.txt | grep "Tests run"
```

## 4. 数据目录隔离

测试**不应**写入仓库内的 `data/`，否则会污染开发数据、并让断言受上一轮残留影响。各测试类的处理方式：

| 测试类 | 数据目录 | 方式 |
|---|---|---|
| 继承 `ApiTestBase` 的用例 | `%TEMP%/travel-api-test-*` | `Files.createTempDirectory` + `@DynamicPropertySource` 注入 `travel.data-directory` |
| 继承 `V2ApiTestBase` 的用例 | `%TEMP%/travel-v2-test-*` | 同上，并把景点库与购票入口配置指向测试副本 |
| `SecurityIntegrationTest` | `travel-server/target/security-test-data` | `@DynamicPropertySource` 指向 `target` 下，随 `mvn clean` 清除 |
| `OptimisticLockConcurrencyTest` | `%TEMP%/travel-concurrency-test-*` | `Files.createTempDirectory` |
| `HealthEndpointTest` | `travel-server/data/`（默认相对路径） | **未做隔离**，属已知技术债；该目录已加入 `.gitignore`，不影响提交 |

> 若新增测试，请优先继承 `ApiTestBase`，避免直接使用默认 `./data`。

**V2 外部依赖的隔离**：`V2ApiTestBase` 会把 `travel.ai.api-key` 与 `travel.amap.key` 强制置空。
本地即使配了 `DEEPSEEK_API_KEY` / `AMAP_KEY` 环境变量，测试也不会发起真实调用、不会产生费用。
高德客户端的解析逻辑用 `MockRestServiceServer` 拦截，不依赖网络；外部接口的可用性不决定测试能否跑通。

## 5. 缺陷回归与并发用例

### 5.1 `KnownDefectTest`——历史缺陷的常驻门禁

该测试类对应测试负责人 2026-11-03 记录的 6 个缺陷：

| 编号 | 缺陷 | 当前状态 |
|---|---|---|
| D-1 | 邀请未注册账号也能成功 | 已修复：返回 400 |
| D-2 | 创建行程不校验标题 | 已修复：空标题返回 400 |
| D-3 | 修改不存在的成员静默成功并递增版本 | 已修复：返回 404，且不递增版本 |
| D-4 | 费用金额允许为负数 | 已修复：返回 400 |
| D-5 | 住宿离店早于入住未拦截 | 已修复：返回 400 |
| D-6 | 并发下乐观锁失效、丢失更新 | 已修复：写锁内完成「校验版本 → 写入」 |

这些用例此前以 `@Disabled` 挂在主干上（保证 `mvn test` 恒绿），**修复后已去掉注解转为常驻回归**。断言写的是需求要求的正确行为，不是当时的实际行为。

### 5.2 `OptimisticLockConcurrencyTest`——并发语义验证

在真实 Servlet 容器下，对同一行程的同一版本并发发起 12 个 `PUT`：

- **期望**：恰好 1 个返回 200，其余 11 个返回 409，最终 `version` 只递增 1。
- **验证点**：不存在"后写覆盖前写"导致的静默丢失更新。
- 该用例依赖真实端口与多线程，执行时间略长，属正常现象。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `mvn: command not found` | Maven 未安装或未进 PATH | 安装 Maven 3.9+，或用 IDE 内置 Maven |
| 编译报 `invalid target release: 21` | 当前 JDK 低于 21 | 切换 `JAVA_HOME` 到 JDK 21 |
| 仓库里出现 `travel-server/data/` | `HealthEndpointTest` 用默认相对路径 | 已在 `.gitignore` 中忽略，可直接删除 |
| 控制台中文显示乱码 | Windows 控制台默认 GBK | 用 `-Dfile.encoding=UTF-8` 运行，或直接看 surefire 报告 |
| 断言随机失败 | 数据目录未隔离，受上一轮残留影响 | 改用 `ApiTestBase` 的临时目录 |
| 首次执行卡很久 | 正在下载依赖 | 耐心等待；可配置阿里云镜像加速 |
