### 4. 逐条研判构建日志中的告警

构建虽然全绿，但日志里有若干 WARNING 和一条容易忽略的 INFO，逐条确认了性质：

- `skip non existing resourceDirectory` 打印两次：父工程对 resources 声明了两个条目，目录不存在时各报一次，属提示信息，无影响。
- shade 报 `module-info.class` 与 `META-INF/LICENSE`、`MANIFEST.MF` 重叠：打 uber jar 的常规提示，Jackson 自带的 `META-INF/versions/9/module-info` 合并后只保留一份，运行时不依赖，可忽略。
- `Mockito is currently self-attaching`：来自 `spring-boot-starter-test` 传递的 mockito-core，当前两个测试都没有使用 mock，暂不处理；将来启用 mock 且 JDK 禁止动态挂载 agent 时，需要在 surefire 中把 mockito 配置为 `-javaagent`。
- **`Using generated security password`**：这是需要记下来的一条。`SecurityConfiguration` 只定义了 `SecurityFilterChain` 和 `PasswordEncoder`，没有提供 `UserDetailsService`，于是 `UserDetailsServiceAutoConfiguration` 自动装配了一个 `inMemoryUserDetailsManager`，用户名为 `user`、密码随机生成并打进日志。当前除 `/api/health` 外全部返回 401，暂无实际暴露面；但账号模块一落地，这个默认用户就会成为后门（能看日志的人都能登录，且与自建账号走两套校验）。已列为进入账号模块时必须先解决的第一项。

## 四、问题与处理

- **IDEA 与命令行构建结果可能不一致**：统一指定 `settings.xml` 与本地仓库路径，两边用同一套依赖解析。
- **默认内存用户隐患**：定位到根因是缺少 `UserDetailsService`，处理方案定为自己实现一个（先内存、后接文件持久化），届时自动配置不再生效，随机密码告警随之消失。
- **打包告警噪音**：确认 module-info 与资源重叠对运行无影响，暂不通过 shade filter 屏蔽，避免为消警告引入多余配置。
- **依赖与实际代码脱节**：Spring AI 依赖已引入但无适配代码，记录在案，防止验收时把"有依赖"当成"已实现"。
