# CLI 使用文档

CLI 是现有 Web 与移动端之外的并列操作入口，使用同一服务端 API、会话认证和权限规则。它不读写服务端数据文件，也不改变现有页面行为。

## 启动前提

- Windows 使用 PowerShell 7（`pwsh`）；需要 JDK 21 和 Maven。
- 仓库不附带含密钥的 `.env`。首次启动前复制示例并填写模型密钥：

```powershell
Copy-Item .env.example .env
notepad .env
```

`DEEPSEEK_API_KEY` 是自然语言模型对话的必需项；`AMAP_API_KEY` 是天气、地点和路线功能的可选项。真实密钥只保存在本机 `.env`，不要提交。

- 从项目根目录构建服务端与 CLI：

```powershell
mvn '-DskipTests' package
```

- 通过启动脚本读取 `.env` 并启动服务端（沙箱支付是唯一支持的交易模式）：

```powershell
.\tools\run-server.ps1
```

直接执行 `java -jar` 不会读取 `.env`；如不使用启动脚本，需在启动前手动设置对应环境变量。

- 另开 PowerShell 7 窗口启动 CLI（脚本会设置终端与 Java 的 UTF-8 编码）：

```powershell
.\tools\run-client.ps1
```

也可指定服务地址：`.\tools\run-client.ps1 http://localhost:8080`。脚本会启用 UTF-8 代码页、输入输出编码和 Java 编码，避免终端按本地代码页解码中文。

有交互终端时进入命令台。支持完整终端控制时启用全屏记录区、固定底部输入、JLine 行内编辑、上下键命令历史和密码遮罩；输入 `/` 后按 Tab 可筛选快捷命令，Ctrl+R 搜索当前进程的命令历史。`/details` 分页展开最近一次工具输出和完整攻略，`/history` 查看本进程对话，`/search <关键词>` 搜索本进程对话；记录只保留在内存中，不写入项目文件。Windows 兼容终端使用原生控制台输入，密码不回显，也不显示星号，不提供这些 JLine 增强能力。两种模式都可输入 `help` 看常用命令，`help all` 看完整命令，`exit` 或 `q` 退出。没有交互终端时只做服务连通性检查。已有一次性调用示例：

若不使用脚本，可在 `-jar` 前加入 `'-Dtravel.cli.forceInteractive=true'` 请求交互模式，并先将终端切换到 UTF-8。无法安全关闭回显且没有原生控制台时，不读取密码。

```powershell
chcp 65001
java '-Dfile.encoding=UTF-8' '-Dstdout.encoding=UTF-8' '-Dstderr.encoding=UTF-8' -jar travel-client/target/travel-client-0.1.0-SNAPSHOT.jar http://localhost:8080 attractions 杭州
```

地图、天气、自驾路线和停车场查询需要在**服务端**配置 `AMAP_KEY`。模型对话等能力按现有项目配置启用；缺少对应密钥时服务端会按已有规则提示或降级。CLI 不保存地图、模型或支付凭据。

## 常用操作

| 命令 | 能力 | 登录要求 |
| --- | --- | --- |
| `status` | 服务及模型状态 | 否 |
| `attractions` / `attractions <关键词>` | 全国景点查询与详情 | 否 |
| `ticket <景点名>` | 官方购票入口和库存核验状态 | 否 |
| `weather <城市>`、`drive <起点> \| <终点> \| [城市]`、`parking <目的地> \| [城市]` | 天气、自驾路段和周边停车 POI | 是，且地图需配置 |
| `route <步行\|公交> <起点经度,纬度> <终点经度,纬度> [城市]` | 既有步行/公交路线 API | 是，且地图需配置 |
| 直接输入旅行需求、`chat <问题>` | 自然语言对话；`chat` 是可选前缀 | 是 |
| `plan <目的地> [天数]` | 行程规划草案 | 是 |
| `itineraries`、`votes <行程ID>`、`advice <行程ID>`、`export <行程ID>` | 行程、候选投票、建议、导出 | 是 |
| `orders`、`order ...` | 沙箱购票闭环 | 是 |

自然语言对话会先集中收集出发地/日期、同行人员、预算、交通和偏好；用户补充后先复述并等确认，回复“确认开始规划”才生成完整草案。想先看粗略版可明确回复“先出初稿”。攻略默认显示逐日表格、景点筛选依据和交通/住宿/餐饮/门票预算分类；`/details` 可滚动查看逐日路线、来源、完整费用与未知项，不依赖 CLI 输出的 localhost 网页链接。路线地图仍需网页工作台；CLI 不显示交互地图或图片卡片。

旅行需求随每轮回复的 `state` 更新，包括日期、预算范围、住宿偏好、必去和排除景点；不依赖最近几条聊天重新推断。天气选日请求会随攻略继续查询，超出预报覆盖的日期明确标注。修改人数、日期、交通后，旧的用户确认费用需要重新核对。住宿检索只给真实地点候选，不代表已有房价、空房或特色核验。

全屏输入区长文本横向滚动；输入 `/` 后按 Tab 显示候选命令，再按 Tab 切换、Enter 填入，再按 Enter 执行；Ctrl+G 关闭菜单。详情和会话历史是分页视图，q 返回输入区。

支持 JLine 的 Windows Terminal 中，复制图片后按 Alt+V 可将剪贴板图像附到当前问题；Ctrl+V 仍是终端的文字粘贴。CLI 会把图片缩放并编码为 JPEG，经服务端发送到配置的视觉模型（默认 `deepseek-flash`，可用 `DEEPSEEK_VISION_MODEL` 改写）。图片随本次请求发送，不写入本地会话记录；模型服务可能按图像 token 计费。没有 JLine 或没有可读图像剪贴板时，不提供图片粘贴。

网页工作台需登录后使用。保存行程后，可用顶栏 TXT 下载文本，或点 PDF 打开打印窗口，在浏览器打印目标中选择“保存为 PDF”。这依赖浏览器的打印能力；当前 PDF 是可打印的文本行程单，不含实时导航地图或景点照片。地图缺少浏览器地图配置或可用坐标时仍显示示意底图，不能作为导航。

浏览器地图单独配置 `BAIDU_BROWSER_AK`（浏览器类型并限制允许来源），不要使用服务端 `BAIDU_AK` 或 Agent Plan Token。未配置时保留路线示意，点击点位可打开百度地图检索与导航。登录后的 `/api/location/map-config` 只返回浏览器 Key。

注册和登录时直接输入实际用户名；命令格式中的尖括号是说明占位符，不要原样输入。`login` 只登录已有账号，创建账号须显式执行 `register`。用户名需为 3-32 位字母、数字或下划线，密码至少 8 位：

```text
register demo_admin
login demo_admin
```

登录后可直接输入自然语言，例如 `我想去黄鹤楼`、`安排两天，预算 1000 元`，不需要输入 `chat`。已知命令（如 `help`、`plan`、`orders`）仍按命令执行；其他输入会作为对话发给助手。发给模型的上下文保留最近 8 条对话消息；CLI 另在内存保留本次进程对话记录，供 `/history` 与 `/search` 查看，但不作为模型上下文。输入 `reset` 清空模型对话上下文，`logout` 或退出 CLI 后会清空上下文；服务端不保存这份 CLI 对话历史。

注册和登录后，当前 CLI 进程会保存服务端会话 Cookie；退出 CLI 后会话 Cookie 不保留。对服务端尚未提供专用 CLI 别名的已有操作，可通过 `api` 命令调用对应 REST API。它只接受 `/api/...` 相对路径，服务端仍负责认证、权限、参数校验和业务逻辑：

```text
api GET /api/itineraries
api GET /api/itineraries/<行程ID>/budget
api POST /api/itineraries {"title":"周末行程","plan":{}}
```

JSON 请求体作为命令剩余文本输入；查询参数可直接放在路径中。已有接口目录与请求体字段见[服务端 REST 接口文档](服务端REST接口文档.md)。

## 购票沙箱演示

本构建没有支付平台 SDK/商户配置/回调验签，也没有景区库存与正式出票适配器。演示商品的单价固定为 `CNY 1.00`，这是**沙箱金额**，不代表票价、报价或有效商品。

1. 搜索景点并选择一个结果：

   ```text
   attractions 西湖
   ```

2. 查看沙箱商品：

   ```text
   order products
   ```

3. 建立订单。景点 ID 可填搜索结果 ID；不需要关联 ID 时用 `-`：

   ```text
   order create - | DEMO_ADMISSION | 1 | 西湖
   ```

   CLI 显示订单状态、支付 URI 和终端二维码。二维码是 `travel-demo://` 演示载荷，不能扫码转账或真实付款。创建订单后 15 分钟未确认会过期；过期状态在查询订单时更新。

4. 执行沙箱确认，服务端核对订单金额和币种、幂等更新状态，并在同一订单更新中自动签发演示票：

   ```text
   order pay <订单ID>
   ```

   可以指定事件 ID 并重复调用以演示幂等行为：

   ```text
   order pay <订单ID> DEMO-EVENT-001
   order pay <订单ID> DEMO-EVENT-001
   ```

5. 查询订单或所有订单：

   ```text
   order show <订单ID>
   orders
   ```

6. 取消未支付订单、演示支付失败，或对已出票演示订单退款：

   ```text
   order cancel <订单ID>
   order fail <订单ID>
   order refund <订单ID>
   ```

   沙箱退款会把票据状态改为 `DEMO_VOIDED`。支付失败后需新建订单；本演示不模拟支付平台实际退款到账。

所有订单、支付、退款和出票状态都会标明 `SIMULATED` 或 `DEMO`。演示票不是景区正式出票、不可入园，也不能作为真实支付、退款或供应商履约凭证。沙箱订单运行数据保存在服务端数据目录下的 `demo_ticket_orders.json`，文件缺失时由 Store 自动创建。

### 真实支付的配置边界

当前 `TRAVEL_PAYMENT_MODE` 只接受 `sandbox`；设置成其他值服务会拒绝启动。适配器通过 `TRAVEL_PAYMENT_PROVIDER`（默认 `sandbox`）和 `TRAVEL_TICKET_PROVIDER`（默认 `demo`）选择 Spring 注册的 `PaymentGateway` 与 `TicketIssuer` 实现；当前构建只附带这两个内置演示实现，可供后续替换和扩展。真实资金交易还需要合规商户及测试收款账户、平台授权和密钥管理、回调验签、商户/订单/金额/币种核对、查单对账、幂等退款，以及适合并发和重启恢复的交易存储。现有 JSON Store 是单进程文件存储，不支持多实例同时写入，也不能据此宣称适用于真实收款。实现这些外部条件前，不会发起真实扣款或转账。

## 自驾与停车

每次 `drive` 表示一个自驾路段；多段行程逐段调用，起点和终点可使用地点名称，建议补上城市以减少地名歧义：

```text
drive 北京南站 | 八达岭长城 | 北京
```

CLI 显示地图返回的驾车距离、耗时预估、路线步骤，并查终点附近停车场 POI。也可单独查询停车：

```text
parking 八达岭长城 | 北京
```

停车 POI 的名称、地址、距离附带高德来源和查询时间。高德当前接口没有可靠停车价格、营业时间或实时车位数据，所以这些字段显示「未知」，并明确显示无实时空位数据。路线距离与耗时是查询时刻的规划结果，不是到达时间保证。高德未配置、不可用或地名未能定位时，CLI 会显示服务端降级原因；现有行程读取与编辑不受影响。

步行与公交原有路线 API 保持可用，使用经纬度坐标（GCJ-02）；也可通过 `api GET /api/location/places?keywords=...&city=...` 查询地点坐标，再调用：

```text
route 步行 116.397,39.908 116.403,39.915
route 公交 116.397,39.908 116.403,39.915 北京
```

## 常见问题

- **401 未登录**：在当前 CLI 会话执行 `login <用户名>`；需要时先 `register`。服务端仍会按原接口权限拒绝未授权操作。
- **高德查询返回 503**：确认服务端进程配置了 `AMAP_KEY`，且账号有对应 Web 服务权限/额度，然后重启服务。
- **停车场没有余位/价格/营业时间**：当前数据源不提供可核验的这些字段，显示未知是预期结果。
- **支付二维码无法付款**：这是不可支付的沙箱演示二维码。真实支付没有接入，切勿据此转账。
- **景区不能用演示票入园**：演示出票只生成本地演示票号，没有景区供应商履约。
- **中文显示异常**：在 PowerShell 7 使用 `.	ools
un-client.ps1` 启动；服务端日志由 `.	ools
un-server.ps1` 设置 UTF-8 编码。

本文件说明的是代码已实现的入口与已知限制；本轮没有运行测试，也不代表团队正式验收或真实外部接口验收。


### 查看和修改完整攻略

登录后可输入“大同玩5天，2人，11月23日出发，住某酒店，老人少走路”，再补充“改为3人”“不去某景点”“首日午餐全团120元”。规划卡完整展示假设时间轴、三餐候选、路线、休息、未覆盖日和逐项费用键。聊天槽位会保留酒店、日期等需求；改变人数等条件后旧确认费用需要重新填写。地图和餐馆信息没有核验的部分明确标记，草案不自动保存。

需要精确控制时，可用现有 `api POST /api/agent/plan <JSON>` 传入 `details`，按响应费用键填写 `confirmedGroupCosts`（全团CNY金额），再重新生成。详见服务端接口文档“完整攻略结构与费用修改”。`plan <目的地> [天数]` 为基础入口，复杂人数、老幼、酒店与费用条件使用对话或 api 命令。

网页工作台的 PDF 按钮直接下载当前攻略（含未保存草案），不再依赖弹窗打印。服务端使用本机中文 TTF 字体；Windows 默认 `C:/Windows/Fonts/simhei.ttf`，其他环境设置 `TRAVEL_PDF_FONT`。字体不随仓库分发。费用可以明确回复“第1天午餐全团已付120元”；预算、期望价格不作为已确认费用。改人数、日期或交通方式时需重新确认旧金额。
