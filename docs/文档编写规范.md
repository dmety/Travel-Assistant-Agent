# 文档编写规范

> 维护：文档负责人　|　最后更新：2026-11-04
>
> 本规范约束仓库内所有 Markdown 文档的术语、结构、命名与提交前检查，目标是让文档与代码保持同源，任何人拿到仓库都能在 10 分钟内定位信息。

## 1. 术语约定

| 用词 | 指代 | 用法 |
|---|---|---|
| **行程**（Itinerary） | 业务对象 | 用户创建的一次出行记录，代码为 `Itinerary` 聚合根。接口文档、代码、测试、新文档统一用「行程」 |
| 旅行方案 | 同「行程」 | 早期文档叫法，仅用于兼容历史表述，新文档不再使用 |
| 技术方案 / 实现方案 | 实现思路 | 描述“怎么写”，如《业务功能技术实现方案》 |
| 专项方案 | 领域设计说明 | 如《多 Agent 与票务能力方案》 |
| 板块 | 行程内五个分区 | `PLAN` / `DAILY` / `TRANSPORT` / `LODGING` / `EXPENSE`，统一称「板块」，不混用「模块」 |

> 判断口诀：**「行程」是数据，「方案」是文档。** 拿不准时看代码里是 `Itinerary` 还是 `*.md`。

## 2. 文档归属

| 文档 | 主要负责人 | 更新时机 |
|---|---|---|
| 需求文档 | 项目经理 | 需求变更、验收标准调整 |
| 架构设计 | 项目经理 / 开发负责人 | 新增模块、分包调整、依赖变化 |
| 服务端 REST 接口文档 | 开发负责人 | 新增或修改接口、错误码变化 |
| 测试说明 | 测试负责人 | 测试分层调整、环境前提变化 |
| 知识库使用文档 | 数据维护者 | 数据结构或检索函数变化 |
| 各版本功能模块 / 三个递进版本 | 项目经理 | 迭代范围调整 |
| 开发日志 | 各岗位本人 | 每次实际工作当天 |

> 文档负责人不代替他人撰写专业内容，负责**一致性**：术语、链接、版本口径、状态描述是否与代码一致。

## 3. 开发日志规范

### 3.1 命名与位置

```
docs/开发日志/<岗位>/<YYYY-MM-DD>-<姓名>.md
```

- 岗位目录固定四个：`项目经理`、`开发负责人`、`测试负责人`、`文档负责人`。
- 日期用实际工作日期，一个人一天一篇；同一天有追加工作就更新原文件，不新建。

### 3.2 结构模板

```markdown
# <岗位>开发工作日志

- 日期：YYYY 年 M 月 D 日
- 项目：Travel-Assistant-Agent（旅行助手）
- 姓名：<姓名>
- 职位：<岗位>
- 阶段：<一句话概括当天做的事>

## 一、今日工作
### 1. <小标题>
<做了什么、依据什么、怎么做的>

## 二、今日产出与证据
| 产出 | 路径或记录 |

## 三、验证结果与当前状态
<能用的部分 / 不能信的部分 / 结论>

## 四、问题与处理
<遇到的坑与解决方式>

## 五、后续安排
1. ...

## 六、职责与参与说明
<本人负责的范围；使用 AI 工具辅助的，如实说明>
```

### 3.3 内容要求

- **必须写基线**：基于哪个提交/分支核查，否则结论无法复现。
- **发现的问题要编号**：缺陷用 `D-1`、`D-2`，文档问题用 `F-1`、`F-2`，并标注严重度（P0/P1/P2/P3），便于跨日志引用与跟踪。
- **结论要能验证**：写“实测 12 路并发仅 1 个 200”，不写“并发应该没问题”。
- **未完成的事项单列**：不要混在已完成里；未做就写“未做”。
- **AI 工具参与要说明**：这是事实陈述，不是免责。

## 4. 提交前自检清单

每次提交文档前逐条过一遍：

- [ ] **相对链接可达**：新增或修改的 Markdown 链接（含图片引用），其目标路径确实存在。
- [ ] **不写本机绝对路径**：禁止 `C:/…`、`D:/…`、`F:/…` 这类路径；示例用相对路径或 `/tmp`。
- [ ] **版本口径正确**：接口/功能适用范围写 `main`，不写个人分支名。
- [ ] **术语一致**：业务对象用「行程」，不新造「旅行方案」。
- [ ] **状态描述与代码一致**：已实现的不要写“待实现”，未实现的不要写“已支持”。
- [ ] **日期与署名**：日志类文档填当天日期与本人姓名。
- [ ] **数字有出处**：写“73 条用例”就应能跑出 73，写“11858 条景点”应能在 `data/` 里数到。
- [ ] **表格格式**：Markdown 表格首行要有表头分隔行，否则渲染成普通文本。

一键检查相对链接（在项目根目录执行）：

```bash
python - <<'EOF'
import os, re
bad, total = [], 0
files = ['README.md']
for dp, _, fs in os.walk('docs'):
    if '.git' in dp: continue
    files += [os.path.join(dp, f) for f in fs if f.endswith('.md')]
for p in files:
    txt = open(p, encoding='utf-8', errors='ignore').read()
    for m in re.finditer(r'\[([^\]]*)\]\(([^)]+)\)', txt):
        link = m.group(2).split('#')[0]
        if not link or link.startswith(('http', 'mailto:', '#')): continue
        total += 1
        if not os.path.exists(os.path.normpath(os.path.join(os.path.dirname(p), link))):
            bad.append((p, link))
print(f'链接 {total} 处，断裂 {len(bad)} 处')
for p, l in bad: print(' ', p, '->', l)
EOF
```

## 5. 更新时机

| 事件 | 需要更新的文档 |
|---|---|
| 合并一个功能 PR | 接口文档（若有接口变化）、README 状态段、本人开发日志 |
| 新增或调整测试 | 测试说明的用例分层与数量 |
| 架构分包变化 | 架构设计的项目树 |
| 需求/范围调整 | 需求文档、各版本功能模块 |
| 每次合并后 | 重跑第 4 节链接检查，确认无断裂 |
