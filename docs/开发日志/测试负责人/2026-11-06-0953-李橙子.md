### 2.3 购票辅助的边界有测试兜住

这部分是本轮唯一新增的业务能力，我把它的约定逐条对到了测试上：

| 约定 | 证据 |
| --- | --- |
| 票价缺失保持「未知」，不补成 0 | `TicketApiTest.missingPriceStaysUnknown`、`TicketAssistantTest.unknownIsNotFree` |
| 未收录的景点明确说明自行前往官方渠道，不生成链接 | `TicketApiTest.unknownAttractionHasNoChannel` |
| 地址协议非法的购票入口在加载时直接丢弃 | `TicketApiTest.invalidUrlIsDropped` |
| 未记录核验日期的入口仍然给出，但提示需再次确认 | `TicketApiTest.unverifiedChannelIsFlagged` |
| 既要 id 又要名称都没给 → 400 | `TicketApiTest.missingQueryIsRejected` |
| 购票登记是用户自报，系统不当成已支付 | acceptance：`ticket registration is explicitly user reported` |
| 登记不自动生成费用，也不重复生成 | acceptance：`ticket registration survives actual process restart without creating expenses`、`registration does not duplicate expenses` |

服务级检查由 17 项增至 21 项，新增 4 项全部围绕购票登记与重启后的一致性。

**这几条设计值得记下来**：未知票价不补零、没有官方入口就不给链接、自报登记不生成费用。这与我此前反复强调的「字段有值不等于已核验」是同一套原则，且这次是写在代码和测试里，不是我口头提醒。
